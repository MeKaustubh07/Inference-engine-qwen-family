## Why so slow: separate processes in the same image and VM, the server stopped

Denormal floats? (`torch.set_flush_denormal`; subnormal values counted in the DeltaNet state after each run)

Same model, natively on the Mac's CPU (fp32): 11.7 tok/s cached (`raw/tests/test_cache.txt`).

Reading: no subnormals, and flushing them changes nothing; one thread is slower than eight, so it is not thread
oversubscription. Every decode step reads all ~3 GB of fp32 weights; at one thread a step took 53 s, i.e. ~60 MB/s,
a storage rate, not a memory one. The weights do not stay resident in the VM and are read back for every token.
Little of it showed up as swap-in (pswpin rose ~9k pages, ~35 MB, during the first 56-token request), which points
to pages of the model file mapped through Docker Desktop's file sharing being evicted and re-read; that last part is
an inference, not measured.

Conclusion: the image is for Linux hosts and CI with memory to spare; on a Mac, run `scripts/serve.py` natively
(Metal).
